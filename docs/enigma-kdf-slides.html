SECURITY SUMMARY

Enigma KDF

What's fixed from historical Enigma, and what still isn't.

The core idea

  • Historical Enigma's failures were almost entirely key management: how keys were generated, shared, and reused. Not the cipher's own math.
  • This system replaces that layer with a real KDF and a real authentication tag.
  • It doesn't touch, and doesn't claim to fix, Enigma's own cryptographic limits.

What this fixes (1/2)

Cillies: operators inventing "random" keys under pressure
Settings derived via HMAC-SHA256. No human ever picks a key by hand.
Doubled message-key encipherment, the 1930s flaw Rejewski broke
Doesn't exist here. No message key is ever encrypted and transmitted.
Shared Grundstellung across a day's traffic, which enabled Banburismus
Message number is a KDF input. Every message gets an independent key.
Physical key material: codebooks, bigram tables. Capture exposed weeks.
Nothing physical exists. Settings are computed on demand, in memory.

What this fixes (2/2)

Indicator transmitted in the clear: a structured daily target
Nothing about settings is ever transmitted. Both sides re-derive independently.
Monthly key sheets, where one leak exposed weeks of traffic at once
Nothing pre-generated or stored in bulk. Settings exist only transiently.
No integrity or authentication: tampering was undetectable
Every message carries an HMAC tag, verified before decrypting.

Enigma's own limits, untouched

  • No letter can ever encipher to itself.
  • The substitution is involutory: encryption and decryption are the same operation.
  • Effective keyspace is roughly equivalent to an 84-bit key, small by modern standards though not casually brute-forceable.

Ciphertext-only cryptanalysis

  • The one real remaining avenue is hill-climbing/genetic-algorithm attacks, the method behind the real 2006 M4 Project breaks.
  • Message length matters a lot. Published successful attacks generally needed 200-450+ characters. Short messages sit below where these reliably converge.
  • Success only costs one message. Breaking one reveals nothing about any other. Every message is independently keyed.

The seed is the single point of failure

  • Every protection in this system assumes the seed itself stays secret.
  • If it leaks, all past and future messages for that pair become instantly and permanently readable.
  • No forward secrecy. Unlike Signal's ratchet, every day's key is always re-derivable from the same seed, forever.

Authentication: real, but limited

  • Can't distinguish the two of you. A valid tag proves someone with this seed sent it, not which of the two. Inherent to any symmetric scheme.
  • Doesn't stop replay. A valid tag doesn't prove a message wasn't simply resent later.
  • Tag is truncated to 64 bits (16 hex characters) for readability. Still ~264 attempts to forge.

No metadata protection

  • Date and message number travel in the clear, by design. That's the tradeoff for never transmitting key material.
  • An observer always knows when messages were sent and roughly how many, even without breaking anything.
  • This system hides content. It does not hide the existence or pattern of communication.

Dependent on the underlying primitives

  • Security assumes HMAC-SHA256 remains sound.
  • Quantum computing's known impact, Grover's algorithm, only halves effective strength. Erosion, not a break.
  • A version marker (v1) is baked into every derived key, but isn't transmitted. Both sides still need prior agreement on which version is in use.

Solvable, but deliberately left as-is

  • Plaintext length leaks exactly. Padding to a fixed block would close this. Not implemented, by choice.
  • Message-number reuse and replay are operator discipline, not system-enforced. A local ledger could fix both automatically. Not implemented, by choice.
  • Neither is a limitation the design failed to notice. Both were considered and skipped, since this is a casual exercise, not a hardened system.

Everything else is operator discipline

  • Seed secrecy and seed strength.
  • Message-number discipline.
  • Endpoint and tool integrity.
  • Content hygiene: avoiding formulaic phrasing, keeping messages short.
  • A cryptographically sound design is only as good as the humans operating around it.

Bottom line

This is a genuine fix for the specific way historical Enigma failed: key management. Built with a real KDF and a real MAC, not an ad hoc scheme.

It is not a cryptographically hardened system by contemporary standards. A bounded keyspace, no forward secrecy, no way to tell the two parties apart.

A well-understood exercise, not a substitute for a vetted modern encryption tool.
